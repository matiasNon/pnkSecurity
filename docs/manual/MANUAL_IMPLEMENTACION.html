1. Resumen y requisitos previos

Todo el ambiente (red, base de datos, almacenamiento, secretos, balanceador, instancias y contenedores) se crea con infra/aws/desplegar.sh sobre la plantilla CloudFormation infra/aws/carta-digital.yaml. Solo la configuración de Cloudflare es manual, como pide el requisito.

RequisitoDetalle
Cuenta AWSAWS Academy Learner Lab (región us-east-1), con el laboratorio iniciado (Start Lab, luz verde). Usa el rol LabRole y el perfil LabInstanceProfile.
TerminalAWS CloudShell (ícono >_ en la consola de AWS). Ya trae AWS CLI, git, openssl y jq; no hay que instalar nada.
Rama del códigoproduccion (la que despliega Jenkins y la que usa el script por defecto). qa y front-back-separados tienen el mismo código.
Dominio (opcional)pnkcarta.me administrado en Cloudflare (sección 5). Sin dominio la app funciona en la dirección del ALB.

2. Arquitectura

Las instancias no tienen IP pública ni SSH; solo el ALB llega a ellas. La base de datos y EFS solo aceptan conexiones desde el Security Group del backend. Las sesiones y los contadores anti fuerza bruta viven en PostgreSQL, así que cualquier instancia atiende cualquier petición.

4. Despliegue en 5 pasos (script único)

1

Abrir CloudShell

En el Learner Lab: Start Lab → esperar la luz verde → botón AWS. En la consola, región N. Virginia (us-east-1) → ícono >_ (CloudShell).

2

Clonar el repositorio

git clone --branch produccion https://github.com/matiasNon/pnkSecurity.git
cd pnkSecurity
3

Ejecutar el script

DOMINIO=carta.pnkcarta.me bash infra/aws/desplegar.sh

El script muestra 5 etapas: credenciales → red (VPC por defecto y 2 subredes en zonas distintas) → certificado HTTPS importado a ACM → stack CloudFormation → espera a que el balanceador vea las 4 instancias sanas. Tarda unos 9-12 minutos (RDS es lo más lento).

Las instancias clonan la rama produccion. Para desplegar otra rama (por ejemplo para probar un cambio): RAMA=qa DOMINIO=carta.pnkcarta.me bash infra/aws/desplegar.sh. Ensayo del 12-11-2026: borrar 7 min 4 s, desplegar 9 min 11 s.
4

Anotar la dirección del ALB

Al final el script imprime la URL y deja todo en infra/aws/salida.env (sin secretos):

cat infra/aws/salida.env      # ALB_DNS=carta-digital-alb-XXXX.us-east-1.elb.amazonaws.com
5

Apuntar Cloudflare al ALB

Editar el CNAME carta en Cloudflare con el nuevo ALB_DNS (sección 5). Es el único paso manual.

Clave del administrador

Se genera al azar y se guarda en Secrets Manager (nunca en el código). Para verla:

ARN=$(aws cloudformation describe-stacks --stack-name carta-digital \
  --query "Stacks[0].Outputs[?OutputKey=='SecretoAdminArn'].OutputValue" --output text)
aws secretsmanager get-secret-value --secret-id "$ARN" --query SecretString --output text | jq -r .password

Usuario: admin@gmail.com. Panel: https://carta.pnkcarta.me/admin.

5. Cloudflare: DNS y HTTPS (paso manual)

#DóndeQué hacer
1Cloudflare → DNS → RecordsCNAME carta → ALB_DNS, Proxied (nube naranja). Si ya existe, solo editar el destino.
2Namecheap → Manage → NameserversSolo la primera vez: Custom DNS con carter.ns.cloudflare.com y lila.ns.cloudflare.com.
3SSL/TLS → OverviewModo Full (no "Full (strict)": el ALB usa un certificado autofirmado y daría error 526).

Guía detallada y verificación: docs/CLOUDFLARE.md.

7. Actualizar la aplicación sin cortar el servicio

Cada instancia clona la rama al arrancar. Para publicar un cambio ya subido a GitHub, se reemplazan las instancias de a una:

cd ~/pnkSecurity && git pull
bash infra/aws/actualizar.sh              # backend y luego frontend (≈ 10 min)
bash infra/aws/actualizar.sh backend      # solo una capa (≈ 5 min)

Se usa en vez de instance refresh porque AWS Academy lo bloquea. Si cambió la plantilla (carta-digital.yaml), primero se vuelve a ejecutar desplegar.sh con las mismas variables (actualiza el stack sin borrar datos) y después actualizar.sh.

La pipeline de Jenkins (Jenkinsfile) hace lo mismo automáticamente desde la rama produccion, solo si pasan lint, SAST, las pruebas Jest y Playwright y el filtro de seguridad (Gitleaks, npm audit + OSV, librerías deprecadas, OWASP Dependency-Check, Trivy y OWASP ZAP).

Qué se parchaCómo se detectaCómo se corrige y despliega
Dependencias de Node (npm)npm audit --omit=dev, OSV-Scanner, OWASP Dependency-Check (pipeline)npm update <paquete> o subir la versión en package.json → npm install → pruebas (scripts/qa.sh) → commit y push → actualizar.sh backend
Paquetes del sistema de las imágenes (Alpine)Trivy (pipeline) sobre carta-backend y carta-frontendLas imágenes se reconstruyen en cada instancia nueva y el frontend ejecuta apk upgrade al construirse: basta con actualizar.sh
Versión de nginx o de NodeTrivy marca el paquete nginx o nodeCambiar la etiqueta base (p. ej. 1.30-alpine → siguiente estable) en el Dockerfile → pruebas → push → actualizar.sh
Sistema operativo de las instanciasBoletines de UbuntuLas instancias nuevas usan la última AMI de Ubuntu 24.04 (parámetro SSM): actualizar.sh las reemplaza ya parchadas
PostgreSQL (RDS)Avisos de RDS / versión menor nuevaConsola RDS → Modificar → versión menor 17.x (aplicar en la ventana de mantenimiento)
Secretos expuestosGitleaks (pipeline)Rotar en Secrets Manager y reemplazar las instancias (actualizar.sh); el rol de la BD se re-aplica en cada arranque
Reversión: git revert <commit> → push → actualizar.sh. Como el reemplazo es de a una instancia, el sitio sigue atendiendo durante el parche y la reversión.

9. Borrar el ambiente y volver a desplegar

bash infra/aws/destruir.sh                 # pide escribir BORRAR; ≈ 6-8 min
DOMINIO=carta.pnkcarta.me bash infra/aws/desplegar.sh   # ≈ 9-12 min

destruir.sh elimina el stack completo (instancias, ALB, RDS sin respaldo final, EFS, secretos, Security Groups), el grupo de registros de CloudWatch y el certificado de ACM. Después de volver a desplegar, el ALB tiene otro nombre: actualizar el CNAME carta en Cloudflare (sección 5, paso 1). La base vuelve a los datos iniciales de las migraciones, que ya incluyen la carta completa con fotos y portadas.
